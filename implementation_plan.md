# Implementation Plan
[Overview]
Extend Open Construction Equipment to v0.5.0 with deterministic, standard-library-only engineering trade studies and native CAD/physics interchange for OCE-CTL-01 and BUNKER-01, spanning multi-physics checks, microgrid powertrains, privacy-preserving rural site screening/adaptation, and DIY/rental/hybrid lifecycle economics.

The release adds five isolated core modules. `physics.py` implements transparent terramechanics, bearing, infinite-slope, buoyancy, concrete-maturity, and weather-derating arithmetic; it is an engineering screening model, not a coupled finite-element or computational-fluid-dynamics solver. `cad_blender.py` converts one immutable synthetic scene model into Wavefront OBJ/MTL, a Blender 4.x Python generator, MuJoCo MJCF, OpenSCAD, and FreeCAD Python without importing any of those applications. `powertrain.py` steps construction-task energy balances through solar/direct supply, LFP battery storage, hydrogen production/storage/reconversion, and gasoline/diesel generation. `geohazard_rural.py` provides the two requested modes: `screen_candidate_parcels` for relative candidates and `adapt_to_existing_site` for an as-is parcel. `economics.py` combines explicitly synthetic tooling, fabrication, labor, wear, rental, energy, and site-adaptation assumptions into whole-DIY, whole-rental, and hybrid comparisons with break-even operating hours.

The current strict loaders, ignored `builds/` outputs, deterministic JSON conventions, six existing commands, frozen SI models, unresolved BUNKER-01 human gates, and offline wheel behavior remain intact. The five new subcommands will be `physics`, `export-cad`, `powertrain`, `site`, and `economics`; `site --mode screen` and `site --mode adapt` select their respective synthetic defaults. Every new CLI command loads and validates its complete input before creating its output directory, writes a `result.json`, and supports deterministic `--json` stdout. The CAD command additionally writes `scene.obj`, `scene.mtl`, `blender_scene.py`, `ctl01_bunker_physics.xml`, `scene.scad`, and `scene_freecad.py`; these generated files are not tracked source files or released manufacturing CAD.

Safety boundaries are architectural invariants, not disclaimers appended afterward. Every result carries `SIMULATED_UNREVIEWED` status, `physicalValidationPerformed: false`, `constructionAuthorized: false`, and unresolved geotechnical, structural, excavation, electrical, hydrogen, fire, environmental, permit/AHJ, and qualified-person gates as applicable. Negative margins, unserved energy, unstable modeled slopes, noise/CO/NOx flags, immature concrete, excessive weather, and insufficient road capacity are findings for further engineering, never operational instructions or automatic approval. No model invokes actuators, generates controller commands, sizes a certified safety function, fabricates hardware, resolves a BUNKER-01 gate, or authorizes excavation, occupancy, confined-space entry, electrical energization, hydrogen production, or equipment operation.

Privacy is fail-closed for both site modes. Inputs contain only anonymous labels and local relative metres; recursive validation rejects GPS/latitude/longitude keys and values, geohashes, street addresses, assessor/APN/parcel identifiers, and unknown location-like fields before calculation or output creation. Reports retain anonymous labels and derived relative distances only, never echo raw location narratives. Mode A is a relative screening aid rather than a purchase recommendation; Mode B produces concept adaptations and signed cost/schedule deltas while leaving qualified site investigation and AHJ decisions unresolved. Synthetic examples must not describe a real property.

At a high level, data flow is strict JSON -> immutable validated dataclasses -> checked finite arithmetic/time-step simulation -> frozen result dataclasses -> canonical JSON and, for CAD only, deterministic text artifacts. Dependencies point inward: `powertrain`, `geohazard_rural`, and `economics` may reuse the common provenance/dataclass utilities established in `physics`; `economics` may consume geohazard deltas; `cad_blender` depends only on the scene types and common checked-arithmetic helpers. No module imports Blender, `bpy`, FreeCAD, OpenSCAD, MuJoCo, NumPy, or JSON Schema at core import or calculation time. Optional applications are manually invoked on emitted artifacts and are never part of the required offline gate.

[Types]
All numeric dataclass fields are finite Python `float` values after parsing unless explicitly optional; Boolean values are rejected as numbers, lengths and other unit-bearing names use SI at runtime, tuples and frozen dataclasses prevent mutation, and parser-level invariants apply before simulation. JSON uses camelCase with explicit unit suffixes while Python uses the snake_case fields below. Currency amounts are synthetic decimal-like values represented as finite `float` for this concept model, never procurement quotes; monetary serialization rounds to six decimal places consistently rather than introducing a third-party decimal dependency.

### `src/open_construction_equipment/physics.py`

**Enums.** `EvidenceStatus(StrEnum)` has the single combined value `SIMULATED_UNREVIEWED = "SIMULATED_UNREVIEWED"`. `WeatherStopCondition(StrEnum)` has `COLD_THRESHOLD`, `HOT_THRESHOLD`, `PRECIPITATION_THRESHOLD`, and `WIND_THRESHOLD`. `ScreeningFlag(StrEnum)` has `WITHIN_MODEL_ASSUMPTION`, `THRESHOLD_EXCEEDED`, and `NOT_APPLICABLE`; it never becomes `PASS`, `SAFE`, or `RELEASED`.

**Shared evidence and geometry dataclasses.** `@dataclass(frozen=True) class SyntheticProvenance` contains `source_type: str`, `statement: str`, `ai_authored: bool`, `owner_supplied: bool`, `site_supplied: bool`, and `physical_validation_performed: bool`; the fixed values are respectively `SYNTHETIC_AGENT_AUTHORED`, nonblank statement, `True`, `False`, `False`, and `False`. Other new modules import this type rather than creating competing provenance semantics. `@dataclass(frozen=True) class TrackContact` contains `length_m: float`, `width_m: float`, and `normal_load_n: float`, all strictly positive, representing one of two equal tracks.

`@dataclass(frozen=True) class TerramechanicsInput` contains `track: TrackContact`, `soil_cohesion_kpa: float >= 0`, `soil_friction_angle_rad: float` in `[0, pi/2)`, `soil_stiffness_kpa_per_m: float > 0`, `rolling_resistance_coefficient: float >= 0`, `traction_efficiency: float` in `(0, 1]`, `slope_angle_rad: float` in `[0, pi/2)`, and `maximum_modeled_sinkage_m: float >= 0`. This is a linear pressure-sinkage and Mohr-Coulomb traction screen; no claim of general Bekker-Wong applicability is made.

`@dataclass(frozen=True) class BearingInput` contains `foundation_length_m: float > 0`, `foundation_width_m: float > 0`, `vertical_service_load_n: float > 0`, `allowable_bearing_pressure_kpa: float > 0`, and `required_factor_of_safety: float >= 1`. `allowable_bearing_pressure_kpa` is explicitly an externally supplied synthetic geotechnical assumption, not a calculated soil capacity.

`@dataclass(frozen=True) class SlopeInput` contains `slope_angle_rad: float` in `(0, pi/2)`, `cohesion_kpa: float >= 0`, `friction_angle_rad: float` in `[0, pi/2)`, `soil_unit_weight_kn_m3: float > 0`, `vertical_slice_height_m: float > 0`, `pore_pressure_ratio: float` in `[0, 1]`, and `required_factor_of_safety: float >= 1`. It represents an infinite homogeneous planar-slope approximation only.

`@dataclass(frozen=True) class BuoyancyInput` contains `displaced_water_volume_m3: float >= 0`, `resisting_mass_kg: float >= 0`, `water_density_kg_m3: float > 0`, and `required_factor_of_safety: float >= 1`. Zero displacement is valid and yields `factor_of_safety is None`, not infinity in JSON.

`@dataclass(frozen=True) class TemperatureInterval` contains `duration_h: float > 0` and `mean_temperature_c: float > -273.15`; intervals must be supplied in chronological relative order but contain no real timestamps. `@dataclass(frozen=True) class ConcreteCuringInput` contains `intervals: tuple[TemperatureInterval, ...]` (nonempty), `datum_temperature_c: float > -273.15`, `reference_temperature_c: float > -273.15`, `activation_energy_j_mol: float > 0`, and `target_equivalent_age_h: float >= 0`. The sample target is synthetic; no strength gain, formwork removal, loading, or stripping criterion is inferred.

`@dataclass(frozen=True) class WeatherSample` contains `temperature_c: float > -273.15`, `precipitation_mm_h: float >= 0`, and `wind_speed_mps: float >= 0`. `@dataclass(frozen=True) class WeatherLimits` contains `minimum_temperature_c: float`, `maximum_temperature_c: float`, `cold_reference_temperature_c: float`, `cold_derating_per_c: float >= 0`, `maximum_precipitation_mm_h: float >= 0`, and `maximum_wind_speed_mps: float >= 0`; minimum < maximum and cold reference >= minimum. Zero precipitation/wind maxima mean any nonzero value is a stop condition rather than a divide-by-zero.

**Input/result dataclasses.** `@dataclass(frozen=True) class PhysicsInput` contains `analysis_id: str`, `provenance: SyntheticProvenance`, `terramechanics: TerramechanicsInput`, `bearing: BearingInput`, `slope: SlopeInput`, `buoyancy: BuoyancyInput`, `curing: ConcreteCuringInput`, `weather: WeatherSample`, `weather_limits: WeatherLimits`, and `required_human_gate_ids: tuple[str, ...]`; IDs are unique, nonempty `PG-\d{3}` values and cannot be omitted.

`TerramechanicsResult` contains `contact_pressure_kpa: float`, `sinkage_m: float`, `maximum_shear_stress_kpa: float`, `available_thrust_n: float`, `rolling_resistance_n: float`, `grade_resistance_n: float`, `net_tractive_margin_n: float`, and `sinkage_flag: ScreeningFlag`. `BearingResult` contains `applied_pressure_kpa: float`, `allowable_pressure_kpa: float`, `factor_of_safety: float`, `utilization: float`, and `threshold_flag: ScreeningFlag`. `SlopeResult` contains `driving_stress_kpa: float`, `resisting_stress_kpa: float`, `factor_of_safety: float`, and `threshold_flag: ScreeningFlag`. `BuoyancyResult` contains `uplift_n: float`, `resisting_n: float`, `factor_of_safety: float | None`, `additional_resisting_mass_kg: float`, and `threshold_flag: ScreeningFlag`. `CuringResult` contains `nurse_saul_maturity_c_h: float`, `arrhenius_equivalent_age_h: float`, `target_equivalent_age_h: float`, and `target_reached: bool`; it deliberately has no strength or authorization field. `WeatherDeratingResult` contains `temperature_factor: float`, `precipitation_factor: float`, `wind_factor: float`, `combined_available_fraction: float`, all in `[0, 1]`, plus `stop_conditions: tuple[WeatherStopCondition, ...]`.

`@dataclass(frozen=True) class PhysicsResult` contains `analysis_id: str`, `status: EvidenceStatus`, `provenance: SyntheticProvenance`, `terramechanics: TerramechanicsResult`, `bearing: BearingResult`, `slope: SlopeResult`, `buoyancy: BuoyancyResult`, `curing: CuringResult`, `weather: WeatherDeratingResult`, `unresolved_human_gate_ids: tuple[str, ...]`, `physical_validation_performed: bool = False`, `construction_authorized: bool = False`, and `operational_release: bool = False`. Dataclass defaults apply only when constructing results in code; the JSON booleans are mandatory and must be false.

`@dataclass(frozen=True) class CadScene` contains `scene_id: str`, `provenance: SyntheticProvenance`, `materials: tuple[MaterialSpec, ...]`, `bodies: tuple[BoxBody, ...]`, `animation: tuple[AnimationKey, ...]`, and `physics: PhysicsSceneSpec`. ### `physics.py`

- `parse_physics_input(data: dict[str, Any]) -> PhysicsInput` — strict envelope and nested-model parser; verifies `schemaVersion == "1.0.0"`, `platform == "OCE-CTL-01"`, `scope == "BUNKER-01"`, synthetic provenance, units, ranges, unique gate IDs, and all invariants in `[Types]`.
- `load_physics_input(path: str | Path) -> PhysicsInput` — strict JSON loader.
- `calculate_terramechanics(model: TerramechanicsInput) -> TerramechanicsResult` — two-track area `A_one=L*B`, total normal load `W=2*N_track`, pressure `p_kpa=W/(2*A_one*1000)`, sinkage `z=p_kpa/K`, shear `tau_max=c+p*tan(phi)`, available thrust `F_t=2*A_one*1000*tau_max*eta`, rolling resistance `F_rr=Crr*W*cos(beta)`, grade resistance `F_g=W*sin(beta)`, and signed margin `F_t-F_rr-F_g`; no stability or drawbar rating is inferred.
- `calculate_bearing(model: BearingInput) -> BearingResult` — `q_kpa=V/(L*B*1000)`, `FS=q_allow/q`, and `utilization=q/q_allow`; `vertical_service_load_n` must be strictly positive at both parser and function boundaries, eliminating zero-denominator ambiguity. Compare FS with `required_factor_of_safety` only to set the screening flag.
- `calculate_slope(model: SlopeInput) -> SlopeResult` — infinite-slope stresses `tau_d=gamma*H*sin(beta)*cos(beta)`, `sigma_n=gamma*H*cos(beta)^2`, pore pressure `u=ru*sigma_n`, `tau_r=c+(sigma_n-u)*tan(phi)`, and `FS=tau_r/tau_d`; equivalent dimensionless form is `c/(gamma*H*sin(beta)*cos(beta))+(1-ru)*tan(phi)/tan(beta)` with all kPa/kN units reconciled implicitly (kN/m² = kPa).
- `calculate_buoyancy(model: BuoyancyInput) -> BuoyancyResult` — `U=rho*g*V`, `R=m*g`, `FS=R/U` when U > 0, and additional mass `max(0,(FS_required*U-R)/g)` using `STANDARD_GRAVITY_MPS2=9.80665`; U = 0 gives `None`, zero additional mass, and `NOT_APPLICABLE`.
- `calculate_concrete_curing(model: ConcreteCuringInput) -> CuringResult` — Nurse-Saul `M=sum((T_i-T_datum)*dt_i)` (negative contributions retained in the raw maturity diagnostic) and Arrhenius equivalent age `t_eq=sum(dt_i*exp[-Ea/R*(1/(T_i+273.15)-1/(T_ref+273.15))])` with `R=8.31446261815324 J/(mol K)`; `target_reached` compares only equivalent age and is not a concrete acceptance decision.
- `derate_weather(sample: WeatherSample, limits: WeatherLimits) -> WeatherDeratingResult` — cold factor `max(0,1-k_cold*max(0,T_ref-T))`, hot factor `max(0,1-(T-T_max)/max(1,T_max-T_min))` above maximum, precipitation factor `max(0,1-p/p_max)` and wind factor `max(0,1-v/v_max)` when maxima are positive; combined available fraction is the product. Crossing any hard threshold adds its stop condition; fractional derating is synthetic productivity only and cannot override a stop condition.
- `evaluate_physics(model: PhysicsInput) -> PhysicsResult` — deterministic composition of the six calculators, preserving every threshold flag and all unresolved PG IDs; no composite `PASS` is emitted.
- `physics_result_json(result: PhysicsResult) -> str` and `write_physics_result(result: PhysicsResult, output_dir: str | Path) -> Path` — convert dataclasses recursively to JSON-compatible primitives and write only `result.json` after `mkdir(parents=True, exist_ok=True)`.
- `bounded_fraction(value: float, name: str) -> float` and `checked_divide(numerator: float, denominator: float, name: str) -> float` — the only new internal arithmetic helpers; reject non-finites, invalid denominators, and fractions outside `[0,1]` due to input/logic errors. Rounding occurs solely at presentation boundaries, never between chained equations.

- `parse_powertrain_input(data: dict[str, Any]) -> PowertrainInput` and `load_powertrain_input(path: str | Path) -> PowertrainInput` — enforce unique tasks, exact keys/ranges, positive interval durations, battery initial/capacity ordering, optional electric acoustic-triple consistency, H2 storage/water bounds, exactly one diesel and one gasoline system, rated-power limits, cost currency, and synthetic provenance.
- `battery_temperature_factor(temperature_c: float, battery: LfpBatterySystem) -> float` — at or above reference return 1; below reference return `max(0,1-k*(T_ref-T))`; below/equal cutoff return 0. Capacity and power use the same declared synthetic factor and cannot become negative.
- `hydrogen_round_trip_efficiency(system: HydrogenSystem, inverter_efficiency: float, converter: PowertrainKind) -> float` — require PEMFC or H2-ICE converter; calculate `eta_chain=eta_electrolyzer*eta_converter*eta_inverter/(1+eta_electrolyzer*E_compression/LHV)` when electrolyzer and compression both draw from the same solar surplus; the denominator follows directly from `m=E_surplus/(LHV/eta_electrolyzer+E_compression)`, cap use by the declared electrolyzer/reconversion power limits, and retain a configuration warning when the resulting example-style chain falls outside 25–32%. For packed battery-assisted DC coupling, report battery and hydrogen chain efficiencies separately rather than averaging unlike paths.
- `estimate_free_field_noise(source_dba: float, reference_distance_m: float, target_dba: float, confined: bool) -> NoiseEstimate` — geometric spreading `L(r)=L0-20*log10(r/r0)` and radius `r=r0*10**((L0-Ltarget)/20)`, bounded below by `r0`; it excludes terrain, barriers, atmosphere, directivity, summation, dose, and code compliance. A confined task always requires review regardless of computed radius. Electric acoustic output uses the optional battery input triple when present; otherwise `noise=None` with an explicit unmeasured low-noise/thermal-signature limitation, because no measured electric dBA input is invented. `conversion_loss_heat_kwh` reports only conversion losses, not a validated infrared signature.
- `simulate_battery_path(task: ConstructionTask, pv: PvSystem, battery: LfpBatterySystem, costs: MicrogridCostAssumptions) -> TaskPathResult` — for each interval calculate electric load `E_load=(E_shaft/eta_shaft+E_aux)*dt/sum(dt)`. Allocate collected PV directly to load, charge remaining PV up to power/temperature/capacity limits with charge efficiency, discharge deficits subject to discharge efficiency/power/SOC, curtail excess, and accumulate unserved energy. Track grid-side versus stored-side values distinctly so energy is neither created nor destroyed.
- `simulate_hydrogen_path(task: ConstructionTask, pv: PvSystem, battery: LfpBatterySystem, hydrogen: HydrogenSystem, converter: PowertrainKind, costs: MicrogridCostAssumptions) -> TaskPathResult` — use the same direct-PV and battery dispatch; only after the battery is full or charge-limited send otherwise-curtailed PV to electrolysis, capped by capacity and available power. For total solar surplus `E_surplus` serving both electrolyzer and compressor, store `m_H2=E_surplus/(LHV/eta_el+E_compression)`, limit electrolysis input `m_H2*LHV/eta_el` by `maximum_electrolyzer_power_kw*dt` plus compression/storage capacity, and on deficit withdraw `m=E_AC/(LHV*eta_converter*eta_inverter)` up to stored mass and `maximum_reconversion_power_kw*dt`. `DAILY_CYCLING` emits the battery-dominance comparison; `SEASONAL_CURTAILMENT` is the niche only when batteries are full and surplus would otherwise curtail; `WINTER_CHP` recovers min(heat demand, thermal input*recovery fraction). Water is production mass*input L/kg; storage, compression, leakage/embrittlement inspections and unresolved H2/fire gates remain explicit.
- `simulate_fuel_path(task: ConstructionTask, pv: PvSystem, fuel: FuelSystem, path: PowertrainKind, costs: MicrogridCostAssumptions) -> TaskPathResult` — match `FuelKind` to path, use PV first, supply remaining electric energy by `fuel_l=E_deficit/(LHV_l*eta_generator)`, compute `refill_events=max(0,ceil(fuel_l/tank_capacity_l)-1)`, `refill_delivery_km=refill_events*refill_delivery_round_trip_km`, flag loads above `maximum_electrical_power_kw`, and estimate noise/exhaust flags. Delivery cost is distance*`delivery_cost_per_km`; refills and delivery are synthetic logistics, not a supplier route. No exhaust dispersion or safe-entry result is produced.
- `allocate_task_cost(path: PowertrainKind, duration_h: float, task_result: TaskPathResult, model: PowertrainInput) -> tuple[float, float]` — sum path-specific CAPEX from `MicrogridCostAssumptions`, allocate `CAPEX*duration_h/service_life_h`, then add fuel, water and hourly maintenance/inspection. Capital is not double-counted across task results in aggregate reporting: both allocated task costs and `SystemCapex` one-time system CAPEX are labeled. Fossil delivery cost and all path-specific conversion-loss heat are also included. Initial `TaskPathResult` energy values are finalized with `dataclasses.replace` after `allocate_task_cost` returns, avoiding partially mutable result objects.
- `compare_powertrains(model: PowertrainInput) -> PowertrainResult` — independently initialize every path at the configured battery/H2 state, preserve task ordering, never share a depleted state between competing paths, emit battery, both hydrogen, diesel, and gasoline task-path results, flag `PEAK_POWER_EXCEEDED` whenever task peak exceeds the applicable discharge/reconversion/generator power limit, and set `daily_battery_preferred` when battery delivered-energy per solar input exceeds H2 with lower modeled operating losses; this is an arithmetic comparison, not universal procurement advice.
- `powertrain_result_json(result: PowertrainResult) -> str` and `write_powertrain_result(result: PowertrainResult, output_dir: str | Path) -> Path` — canonical result output, rejecting any energy closure error > `1e-9 kWh` before writing.

### `geohazard_rural.py`

- `reject_private_location_data(value: Any, path: str = "site") -> None` — recursively inspect every JSON key and string before typed parsing. Case-insensitive forbidden keys are matched at whole-identifier/underscore or camelCase token boundaries, never by arbitrary substring, so valid fields such as `translation_m` cannot trigger a `lat` false positive. Forbidden key tokens include latitude, longitude, lat/lon, GPS, GNSS, geohash, plus_code, street, address, postcode, ZIP, APN, assessor, deed, parcel_id, tax_id, legal_location, and real_property_id; explicitly allow only `anonymous_label`, `vertices_local_m`, `x_m`, `y_m`, and relative distance fields as location-adjacent vocabulary. Detect textual lat/lon assignments, `GPS`/`GNSS` coordinates, street-address patterns, and URLs with geolocation queries. False positives in ordinary derived reasons are avoided by scanning raw input keys/strings, not generated explanatory text.
- `parse_geohazard_input(data: dict[str, Any]) -> CandidateParcel | ExistingSite | tuple[CandidateParcel, ...]` — call privacy rejection first, then validate the discriminant `mode`; screen requires nonempty unique candidate labels, adapt requires exactly `EXISTING-SITE`; neither accepts authorization or resolved-gate fields.
- `load_geohazard_input(path: str | Path) -> CandidateParcel | ExistingSite | tuple[CandidateParcel, ...]` and `load_geohazard_document(path: str | Path) -> dict[str, Any]` — strict JSON plus envelope preservation needed for deterministic report metadata.
- `minimum_feature_distance(feature: LocalFeature) -> float` — compute minimum Euclidean distance from the unnamed local structure reference point `(0,0)` to a segment or polygon boundary, returning 0 if inside an area; this is a relative geometric screening distance, not a survey. Missing professional distances remain null/UNKNOWN.
- `assess_risks(factors: SiteFactors) -> tuple[RiskAssessment, ...]` — evaluate closed depressions at `distance <= closed_depression_review_distance_m`, karst depth at `depth <= karst_depth_review_threshold_m`, supplied subsidence level, null groundwater or `depth <= groundwater_review_depth_m`, waterway/wetland violations at `distance < required_setback` (equality remains only a modeled, still-AHJ-reviewed boundary), flood depth > 0, slope FS < required FS, expansive-clay level, land shift > its declared threshold, insolation < declared minimum, winter design temperature < declared minimum, known axle overload, `minimum_overhead_clearance_m < transport_height_m + required_overhead_clearance_m`, and sightline/acoustic privacy. Acoustic distance uses `r=15*10**((source_dba_at_15m-max(receiver_target_dba,ambient_dba))/20)` bounded below by 15 m only as a free-field geometric comparison; actual receiver distance below r requires review, never a compliance decision. Unknown data always yields UNKNOWN+required review; no risk score can average away a high-risk or unknown domain.
- `assess_permits(model: PermitProfile) -> tuple[PermitAssessment, ...]` — ground disturbance >= SWPPP threshold triggers grading/SWPPP review; well/septic and culvert fields trigger their specialist/AHJ topics; rural unincorporated agricultural/nonhabitable utility conditions may produce `EXEMPTION_CANDIDATE` only for the named candidate topic, while every result additionally has `AHJ_CONFIRMATION_REQUIRED` until a human determination exists.
- `screen_candidate_parcels(parcels: Sequence[CandidateParcel]) -> ScreeningResult` — independently assess each candidate; reject only explicit modeled hard constraints such as inside a required setback or axle load above a known limit, mark high/unknown/triggered cases `ENGINEERING_REVIEW`, and otherwise use `RELATIVE_CANDIDATE`. Deterministic severity sorting does not produce a purchase ranking or suppress unknowns.
- `adapt_to_existing_site(site: ExistingSite) -> AdaptationResult` — evaluate the as-is factors and accumulate the following adaptations without recommending parcel rejection:
  1. If known groundwater or karst depth is shallower than baseline excavation depth (or high subsidence makes deep excavation unsuitable for the model), select `SEMI_BURIED_EARTH_BERMED_MOUND`, add `SHALLOW_MOUND`, retain specialist design, and do not compute a construction excavation plan.
  2. If expansive clay is MODERATE/HIGH/UNKNOWN or land shift exceeds `SlopeProfile.land_shift_review_threshold_mm_year`, replace strip-footing concept with `STIFFENED_CELLULAR_RAFT_ON_GEOGRID`, with geotechnical/structural gates unresolved.
  3. Calculate buoyancy from groundwater-influenced displaced volume where supplied using `WaterProfile.buoyancy_displaced_volume_m3`, `WaterProfile.resisting_mass_kg`, and `WaterProfile.water_density_kg_m3`; if FS is below the site requirement, add dead-weight collar volume `max(0,(FS_req*U-R)/(g*(rho_concrete-FS_req*f_submerged*rho_water)))`, which accounts for both collar mass and its specified displaced-water fraction. Reject a nonpositive density denominator and escalate to specialist design rather than returning an infinite collar volume; use `WaterProfile.concrete_density_kg_m3`. Do not invent densities, displaced volumes, resisting masses, or collar geometry.
  4. When anti-flotation or flood/groundwater is a concern, add `REDUNDANT_SOLAR_DRAINAGE` with two independently modeled solar sump units and battery backup as an adaptation description, but count `redundant_solar_sump_count=2` only as a concept allocation, never a drainage design or reliable-life-safety system.
  5. Privacy berm request volume is `length*cross_section`; placed volume is `min(request,available_compacted_spoil)` and the result reports any shortfall instead of conjuring spoil. Placement follows shallow-mound/privacy/noise and geotechnical review, not an instruction to dump or compact soil near a structure.
  6. Add waterway/wetland and access adaptations/reviews for violations/unknowns; software cannot move a real feature or guarantee a permit. For each triggered adaptation, attach the matching explicit `AdaptationAssumption` under its generated SA ID and missing-assumption errors abort the complete result. `HumanGate` records are emitted in sorted SG order and remain unresolved.
- `geohazard_result_json(result: ScreeningResult | AdaptationResult) -> str` and `write_geohazard_result(result: ScreeningResult | AdaptationResult, output_dir: str | Path) -> Path` — output anonymous derived results only, omit raw feature vertices/narratives, preserve every unresolved gate, and reject JSON non-finites.

### `economics.py`

- `parse_economics_input(data: dict[str, Any]) -> EconomicsInput` and `load_economics_input(path: str | Path) -> EconomicsInput` — enforce all exact keys, currencies, unique IDs/policies, allowed pathway references, sorted unique evaluation hours, resolvable labor role, available labor, and nonnegative assumptions.
- `fabrication_totals(model: EconomicsInput, pathway: AcquisitionPathway) -> tuple[float, float, float, float]` — for owned selected items return `(material_cost, component_cost, labor_hours, fixed_tooling_capex)` using `quantity*(unit cost)` and `quantity*labor_hours_per_unit`; labor cost uses the named role, and hourly wear is accrued on operating hours separately. Tooling is included only if selected by an owned item relationship, avoiding charging every possible shop tool to every pathway.
- `rental_cost(item: RentalItem, operating_hours: float) -> tuple[float, float, float]` — linear lifecycle expected rental accrual is `rate_per_billing_unit*operating_hours/unit_hours`; mobilization cost is `delivery_per_mobilization*mobilizations_per_project` once per modeled project, and energy is `fuel_or_energy_per_h*billable_operating_hours`. Return `(rental, mobilization, energy)` separately. Document that this proration is not an invoice; integer day/week minimum rental quotes require external human-vendor inputs and are not fabricated.
- `evaluate_pathway(model: EconomicsInput, policy: PathwayPolicy, operating_hours: float) -> PathwayCost` — sum fixed DIY/HYBRID shop CAPEX, materials/components, one-project labor and mobilization/site deltas with variable wear/maintenance, rental and energy per operating hour. Fixed ownership allocation is `annual_fixed_ownership_cost*operating_hours/ownership_hours_per_year`; DIY/HYBRID energy adds `owned_microgrid_energy_cost_per_h*operating_hours`; tool maintenance/replacement reserve adds `maintenance_per_h + startup_capex/service_life_h` per operating hour; only selected IDs contribute. At zero hours, fixed setup costs remain while variable reserves and prorated rentals are zero. Labor hours are a one-project quantity, not multiplied by evaluation hours unless a separate repeated-project scale is explicitly added.
- `break_even(left: PathwayCost, right: PathwayCost) -> BreakEvenResult` — require equal `left.operating_hours == right.operating_hours` and use the same zero-hour and evaluated-hour line aggregation to form `C_left(H)=F_left+V_left*H` and `C_right(H)=F_right+V_right*H`. If `V_left == V_right`, return no finite crossing (`None`) and identify the cheaper everywhere path or exact tie. Otherwise candidate `H*=(F_right-F_left)/(V_left-V_right)`; accept only finite `H* > 0`, require both total functions to be nonnegative at the crossing, and identify left/right path below/above by evaluating at zero and `H*+max(1,abs(H*))`. Negative candidate means no positive-hours break-even, not a misleading negative operating duration.
- `compare_pathways(model: EconomicsInput) -> EconomicsResult` — evaluate each policy at each requested horizon in pathway-then-hour order and calculate pairwise break-even from the zero-hour and full-line cost structures, not rounded display totals. At repeated identical horizons return one result per requested unique horizon.
- `economics_result_json(result: EconomicsResult) -> str` and `write_economics_result(result: EconomicsResult, output_dir: str | Path) -> Path` — serialize after checking sum of cost lines equals declared totals within `1e-6` currency units and every currency matches.
- Shared private helpers `_selected_tooling`, `_selected_fabrication`, `_fixed_variable_totals`, and `_validated_cost` are confined to this module; they do not alter existing BOM data or replace the current `bom.py` summary command.
